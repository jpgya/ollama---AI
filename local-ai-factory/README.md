# Local AI Factory

Ollama上のローカルLLMを使い、ソフトウェア改善案を**候補として隔離生成・検査・記録**するPython製CLIです。外部の有料AI APIは使用しません。本番反映や対象プロジェクトへの自動書き戻しは行いません。

> **安全上の重要事項:** LLM出力は信頼できない入力です。実験候補は `factory-data/artifacts/` 以下に保存されます。macOSの `sandbox-exec` が利用できる場合に限り、テストプロセスのネットワークとホームディレクトリへのアクセスを制限します。macOSのサンドボックスは完全な隔離を保証するものではなく、レビューなしで候補を本番利用しないでください。静的セキュリティ検査も完全な脆弱性検出器ではありません。

## 動作環境とセットアップ (macOS Apple Silicon)

Python 3.11以上、Node.js 18以上、Git、Ollamaが必要です。依存は標準ライブラリのみで、テスト用にpytestを使います。

1. Ollamaをインストール・起動し、16GBメモリ機でも扱いやすい7B級モデルを取得します。

   ```sh
   brew install ollama
   ollama serve
   # 別ターミナル
   ollama pull qwen2.5:7b
   ```

2. 工場とPython仮想環境を準備します。

   ```sh
   cd local-ai-factory
   python3 -m venv .venv
   source .venv/bin/activate
   python -m pip install -e '.[dev]'
   ```

3. そのまま起動すると `config.json` と実験用データ保存先を自動作成し、工場自身 (`local-ai-factory/`) を対象に開発サイクルを開始します。別のリポジトリを対象にする場合だけ、`config.json` の `project_root` を変更します。対象リポジトリのソースは読み取り専用で扱い、候補は `data_root` の配下に作られます。

4. チャット画面と開発工場を起動します。

   ```sh
   # local-ai-factory/ の中から:
   npm start

   # または、このフォルダーの親 (ollama自立型AI/) から:
   npm start
   ```

   `http://127.0.0.1:8765` を開き、Ollamaのチャットと進化タイムラインを表示します。新規設定は同梱プロジェクトを自動で対象にし、既存の初期テンプレート設定も自動移行します。既にOllamaが稼働中ならそのまま接続し、停止中で `ollama` コマンドがある場合は `ollama serve` をバックグラウンド起動します (初期設定)。npm依存のインストールは不要です。起動時にブラウザを開かない場合は `LOCAL_AI_FACTORY_OPEN_BROWSER=0 npm start` とします。`npm start -- --config /path/to/config.json` で別設定を指定できます。工場は同時にバックグラウンド起動し、Ctrl+CでWeb画面と工場を停止します。自動起動したOllamaサーバーは通常の常駐サービスとして残ります。不要なら `start_ollama_if_stopped` を `false` にしてください。

   Macへのログイン後も自動起動し、ターミナルを閉じた後も工場を常駐させる場合は、LaunchAgentを登録します (登録後すぐ起動します)。

   ```sh
   # ワークスペース親フォルダーから
   npm run service:install

   # 停止・自動起動解除 (成果物とログは保持)
   npm run service:uninstall
   ```

5. 初回確認とテスト:

   ```sh
   local-ai-factory --dry-run once
   local-ai-factory models
   pytest
   ```

`config.json` は秘密情報を含めないでください。工場はプロジェクト内の `.env`、秘密鍵名のファイル、典型的な秘密鍵文字列をコンテキストから除外しますが、すべての秘密情報を検出できるわけではありません。対象プロジェクトに秘密情報がないことを事前に確認してください。

GitHubへ公開するときは、学習・実験で蓄積した記録や生成成果物 (`factory-data/` 以下)、ローカル設定 (`config.json`、`tasks.json`) はコミットしないでください。ワークスペース直下とこのディレクトリの `.gitignore` で除外しています。これらのファイルはローカルには残り、削除されません。

## チャットとWeb検索

チャットとダッシュボードは `web_host` (初期値 `127.0.0.1`) / `web_port` (初期値 `8765`) のローカルアドレスでのみ待ち受けます。ネットワーク越しの公開や認証なしの外部公開は行いません。画面の「Web検索を使う」を選んだ会話、または「知識を探す」欄からの検索に限り、検索語がBingの検索サービスへ送られます。検索結果は抜粋とURLだけを取得し、ページ全体の自動取得はしません。

Web検索結果は自動学習・自動保存しません。内容を確認して「工場の知識に保存」を押すと `factory-data/datasets/web_knowledge.jsonl` に重複除去して記録し、以後のチャットと改善タスク/実装プロンプトの参考資料に含めます。保存資料は未検証データとして扱われ、命令として実行・遵守しないようモデルへ明示します。追加学習やモデル重みの変更ではありません。

## CLI

```sh
local-ai-factory --dry-run once  # 設定・対象・負荷を確認。LLM問い合わせや書き込みなし
local-ai-factory once            # 1タスクの候補を生成して評価
local-ai-factory once --task "既存のCSV処理に境界値テストを追加"
local-ai-factory start           # 逐次ループ。Ctrl+Cで停止
local-ai-factory pause
local-ai-factory resume
local-ai-factory stop
local-ai-factory status
local-ai-factory tasks
local-ai-factory report
local-ai-factory models
```

`start` はフォアグラウンドで動きます。LaunchAgent使用時の停止・一時停止・再開は別ターミナルから同じ設定ファイルで実行します。`stop` は安全な停止要求を保存し、現在の処理が終わった後に停止します。デフォルトで同時実行は1、1サイクルあたり1タスクです。連続エラーが設定回数に達すると、工場は停止せず自動回復待ちに入り、指数バックオフで再試行します (初回60秒、最大15分)。人が明示的に `pause` した場合は `resume` まで停止を維持します。データベース、実験JSON、承認/却下成果物、知識ファイルは `data_root` に永続保存され、再起動後も保持されます。ここでの「学習記録」は検証結果・失敗・承認成果物・保存知識の蓄積であり、モデル重みを変更する追加学習は未実装です。

## 品質ゲートと成果物

- 生成コードを候補ディレクトリへコピーし、構文検査、ASTベースの危険API検出、pytestを実施します。
- テストが存在しない、実行を無効にした、sandboxが必須なのに使用できない、といった場合は**評価未完了＝不合格**です。これら必須条件を設定で無効化することはできません。
- テスト成功、構文検査成功、設定されたセキュリティ検査を満たした場合のみ `approved` になります。スコアで必須条件を上書きしません。
- `factory-data/artifacts/approved/`, `rejected/`, `experiments/`, `models/` に区分し、各成果物の `metadata.json` にID、日時、モデル、タスク、評価、ハッシュを記録します。SQLiteの一意ハッシュ制約で重複を拒否します。
- 実行記録・リトライイベントは `factory-data/factory.sqlite3`、詳細ログは `factory-data/logs/factory.log`、品質レポートはCLIの `report` で確認します。
- 合格候補であっても元リポジトリには自動反映せず、Gitコミットも自動作成しません。人がレビューした後、手動で取り込み・コミットしてください。

## 設定と負荷制御

設定例は `config.example.json` にあります。Ollama URLはローカルホストのみ許可し、コンテキスト長、生成トークン数、HTTP/実験タイムアウト、メモリ・ロード・空きディスク閾値、リトライ、待機時間、コンテキスト上限を指定できます。

macOSでは `memory_pressure -Q` (利用できない場合は `vm_stat`) とシステムロードを確認し、閾値超過時はサイクルを開始しません。`vm_stat` フォールバックのメモリ値はページ統計からの概算です。ほかのOSではメモリ負荷を未計測とし、ディスクだけ検査します。実測に合わせて閾値を保守的に調整してください。異常時にOllama自体を再起動することはありません。

`require_macos_sandbox: true` が初期値です。macOS以外、または `sandbox-exec` がない環境ではテスト評価が未完了となり、合格しません。サンドボックスを無効にすればテストは実行できますが、信頼できないテストコードを通常の権限で実行するため、推奨しません。

## 保管データの整理

自動削除は安全性を優先して実装していません。`factory-data` を削除・整理する場合は工場を停止し、SQLiteの参照と必要な成果物を確認してから手動でバックアップ・整理してください。

## 現在の実装範囲と制限

- 実装済み: Ollama接続、CLI、ローカルチャットとストリーミング応答、リアルタイム進化ダッシュボード、明示操作によるWeb検索と知識保存、タスクキュー、逐次実行、隔離候補、構文・テスト・限定的なセキュリティゲート、重複ハッシュ防止、ログ・レポート、負荷閾値、停止/一時停止/再開。
- 追加実装が必要: MLX-LMの学習データ作成・LoRA学習・固定評価セット比較、Discord Bot、Gitブランチ/コミット自動生成、より強いOSコンテナ隔離、詳細な型検査・複雑度・性能ベンチマーク。これらを実装済みとは扱いません。
- タスク自動生成はOllamaの提案に依存します。重複提案は停止して再試行せず、手動タスクを追加・編集してください。
- モデルは自己申告の評価だけで採用されません。モデル学習・自動採用機能自体は未実装です。
